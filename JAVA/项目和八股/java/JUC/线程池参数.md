- 线程池的构造函数有七个参数，分别是核心线程数（**corePoolSize**）、最大线程数（**maximumPoolSize**）、空闲线程存活时间（**keepAliveTime**）、时间单位（**TimeUnit**）、线程池任务队列（**workQueue**）、线程工厂（**ThreadFactory**）和拒绝策略（**RejectedExecutionHandler**）。
1. **corePoolSize**：核心线程数，线程池中长期存活的线程数
    - 如果线程池中的线程数量小于核心线程数，这些线程处于空闲状态也不会被销毁
2. **maximumPoolSize**：最大线程数，线程池最多能创建的线程数
    - 当核心线程已满，任务队列已满时，如果当前线程小于最大线程数，就会创建新的线程执行此任务，否则触发拒绝策略。
3. **keepAliveTime**：空闲线程存活时间。
    - 当线程数大于核心线程数时，如果每个线程的空闲时间超过了keepAliveTime,这个线程就会被销毁，销毁线程数=当前线程数-核心线程数
4. **TimeUnit**：时间单位，keepAliveTime的时间单位。
5. **workQueue**：线程池的任务队列，线程池存放任务的队列，没有空闲线程执行新任务时，存储所有待执行任务。
6. **ThreadFactory**：创建线程的工厂，通过此方法设置线程的优先级、线程命名规则以及线程类型（用户线程/守护线程）。
7. **RejectedExecutionHandler**：拒绝策略，当线程池的任务超出线程池队列可以存储的最大值之后，执行的策略。
- 线程池的参数决定了线程池的并发能力，资源占用和任务处理策略，需要根据实际场景进行合理配置

# CPU密集型和IO密集型线程池大小参数不同
CPU 密集型任务主要消耗 CPU 时间，线程数过多会导致大量上下文切换，因此线程数通常接近 CPU 核心数；IO 密集型任务大量时间处于等待 IO 状态，如果线程数设置过少，会导致 CPU 空闲，因此可以创建更多线程，提高 CPU 利用率。实际线程池大小需要结合任务等待比例、CPU 核数以及系统负载综合调整。
