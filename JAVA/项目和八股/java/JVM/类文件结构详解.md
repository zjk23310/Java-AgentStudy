# 字节码
JVM能够理解的代码就是字节码。其不面向任何特定处理器，只面向虚拟机。字节码不针对特定机器，java程序无序重新编译就可以在多种不同操作系统的计算机运行。.class文件是不同语言在Java虚拟机之间的重要桥梁.字节码本身是一种二进制数据，但是它并非直接由CPU执行，而是由JVM中的**字节码执行引擎**来负责解释或编译执行

# Class文件结构总结
构成Class文件的有两种基本的数据类型，分别是**无符号数**，可以用u1、u2、u4、u8来表示，表示n个字节的无符号数
**表**是有多个无符号数或其他表构成的符合结构，习惯以_info结尾
整个Class文件本质就是一张表
```
ClassFile {
    u4             magic; //Class 文件的标志
    u2             minor_version;//Class 的小版本号
    u2             major_version;//Class 的大版本号
    u2             constant_pool_count;//常量池的数量
    cp_info        constant_pool[constant_pool_count-1];//常量池
    u2             access_flags;//Class 的访问标记
    u2             this_class;//当前类
    u2             super_class;//父类
    u2             interfaces_count;//接口数量
    u2             interfaces[interfaces_count];//一个类可以实现多个接口
    u2             fields_count;//字段数量
    field_info     fields[fields_count];//一个类可以有多个字段
    u2             methods_count;//方法数量
    method_info    methods[methods_count];//一个类可以有多个方法
    u2             attributes_count;//此类的属性表中的属性数
    attribute_info attributes[attributes_count];//属性表集合
}
```
上面展示了一个ClassFile所包含的内容
## 魔数
每个 Class 文件的头 4 个字节称为魔数（Magic Number）,它的唯一作用是**确定这个文件是否为一个能被虚拟机接收的 Class 文件**。Java 规范规定魔数为固定值：0xCAFEBABE。如果读取的文件不是以这个魔数开头，Java 虚拟机将拒绝加载它
## Class 文件版本号
紧接着魔数的四个字节存储的是 Class 文件的版本号：第 5 和第 6 个字节是**次版本号**，第 7 和第 8 个字节是**主版本号**。高版本的虚拟机可以执行低版本编译器生成的Class文件，但是低版本的虚拟机不能执行高版本编译器生成的Class文件
## 常量池
紧接着主次版本号之后的是常量池，常量池的数量是 `constant_pool_count-1`（**常量池计数器是从 1 开始计数的，将第 0 项常量空出来是有特殊考虑的，索引值为 0 代表“不引用任何一个常量池项”**）。
常量池存放：字面量（文本字符串、final常量值）、符号引用（类和接口的全限定名、字段和方法的名称和描述符等）。每个常量都是一张表，每个常量以u1类型的tag开头，用于表示常量的类型。

这里说一个需要注意的地方
java类的字节码文件放在哪里呢？编译后的java类会生成.class文件，它会根据不同的项目放在不同的位置，不过这个不是很重要。Class文件中的常量线程池位于什么位置呢？常量线程池在第10个字节便宜之后开始，但是常量池项是变长的，不能简单按固定长度跳转。Class文件主要存放字面量和符号引用
对于运行时的常量池则需要不同考虑。类的元数据、方法字节码、运行时常量池都在方法区，或者说是元空间。但需要注意字符串常量池在堆中
如果对元空间或者堆感到不清楚可以查看[[Java内存区域详解]]
## 访问标志
u2类型，表示类或接口的访问权限与属性，确定是public还是final，是类还是接口
### 类索引、父类索引、接口索引
三部分共同确定类的继承关系
this_class指向常量池中一个 `CONSTANT_Class_info` 的索引，代表当前类的全限定名。
super_class指向父类的全限定名。除 `java.lang.Object` 外，所有类的 `super_class` 都不为0。
interfaces一个 `u2` 类型的数组，存储了类实现的所有接口的索引。
## 字段表集合
描述类或接口中声明的**成员变量**（不包括方法内的局部变量）。每个字段由一个 `field_info` 结构描述
```java
field_info {
    u2 access_flags;      // 访问修饰符 (public, private, static, final等)
    u2 name_index;        // 字段名，指向常量池中的Utf8字符串
    u2 descriptor_index;  // 字段描述符，指向常量池中的Utf8字符串，用于描述数据类型
    u2 attributes_count;
    attribute_info attributes[attributes_count]; // 属性表，存放额外信息
}
```
## 方法表集合
描述类或接口中声明的**方法**。结构与 `field_info` 类似，每个方法由 `method_info` 描述。方法表的**属性表**中通常会包含一个至关重要的 **`Code` 属性**，它存放着该方法经编译后的**字节码指令**
！！！方法的具体逻辑不再在方法表的属性表中的code属性字段中。方法的参数类型放在常量池中，通过descriptor_index指向。方法的参数名并不一定放在Class文件中，如果使用反射Method.getParameters获得不到名字，则可能是因为编译时没有加-parameters，方法的具体参数值在运行时帧栈的局部变量表中。
```
method_info
├─ access_flags
├─ name_index        ──→ 常量池 Utf8："add"
├─ descriptor_index  ──→ 常量池 Utf8："(II)I"   <-- 参数类型在这
└─ attributes[]
    ├─ Code
    │   ├─ max_stack / max_locals
    │   ├─ code[]                    <-- 方法逻辑（字节码指令）
    │   ├─ exception_table[]
    │   └─ attributes[]
    │       ├─ LineNumberTable
    │       ├─ LocalVariableTable    <-- 参数/局部变量名（调试信息）
    │       └─ StackMapTable
    └─ MethodParameters              <-- 参数名（-parameters 编译时）
```
## 属性表集合
属性表是一种**灵活的扩展机制**，用于描述某些场景的专有信息。它可以出现在类、字段表、方法表中。其通用结构如下
```
attribute_info {
    u2 attribute_name_index; // 属性名，指向常量池中的Utf8字符串
    u4 attribute_length;     // 属性值的长度（不包括前6个字节）
    u1 info[attribute_length]; // 属性具体内容
}
```
除了上面提到的 `Code` 属性，常见的属性还有 `ConstantValue`（用于 `final` 常量）、`Exceptions`（方法抛出的异常）、`LineNumberTable`（字节码行号与源码行号的映射）等。
