大多业务，读取操作远大于写操作，读取操作不会修改原资源，每次读取操作都加锁是一种资源浪废。为了将读操作性能发挥到极致，`CopyOnWriteArrayList` 中的读取操作是完全无需加锁的。更加厉害的是，写入操作也不会阻塞读取操作，只有写写才会互斥。这样一来，读操作的性能就可以大幅度提升。
CopyOnWrite的核心是使用了写时复制的策略
在读取的时候会共同获取相同指针，指向同样资源，知道某个调用者视图修改资源，系统就会复制一份副本给调用者，其他调用者所见到的最初资源不变。
# 写时复制的缺点
1. 内存占用：每次写操作都需要复制一份原始数据，会占用额外的内存空间，在数据量比较大的情况下，可能会导致内存资源不足。
2. 写操作开销：每一次写操作都需要复制一份原始数据，然后再进行修改和替换，所以写操作的开销相对较大，在写入比较频繁的场景下，性能可能会受到影响。
3. 快照一致性：迭代器会保留创建时底层数组的快照，后续修改不会反映到这个迭代器中。
# CopyOnWrite的源码
CopyOnwrite的源码还是比较简单的，而且也不是很多，所以可以把要点在此写下
## 实现接口
其实现了List、RandomAccess、Cloneable、Serializable
## 初始化
有一个无参构造函数和两个有参构造函数
无参构造函数会将当前的Array指向一个Object\[0]的数组
有参构造分为按照集合的迭代器
包含一个指定数组的副本
方法都比较简单主要是Arrays.copyOf的运用，如果忘记了Arrays工具类的相关知识可以去[[Java集合的一些知识]]查看对应的网址
## 插入元素

插入元素是CopyOnWrite中加锁的方法，加锁之后会获取原来的数组，并复制数组到长度为原数组+1的数组中在最后位置加入新元素。然后设置Array为新的数组
## 读取元素
读取元素分为两步，读取当前元素的引用，直接从数组中获取下标为index的元素，所以也不难
不过由于过程没加锁，可能会出现读取的元素是修改数组之前的元素
## 读取列表元素个数
方法很简单直接获取当前数组的长度就好了（CopyOnWrite数组并不会想ArrayList出现空缺的情况）
## 删除元素
其分段复制主要使用分段复制的方法，创建一个长度为原来数组长度减一的数组，如果删除元素为最后元素就直接复制数组，如果不是就分段复制到新数组，复制之后将当前数组指针指向新数组
## 判断元素是否存在
contain使用indexOf，containsAll则遍历使用IndexOf本质没区别
