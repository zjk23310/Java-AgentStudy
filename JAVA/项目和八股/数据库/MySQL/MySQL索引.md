*这里可以讲一下怎么理解索引下推*：
个人认为，如果我使用一个联合索引，并且前面的索引条件被使用了，但是后面的索引并不能够被用到，可是却能够在数据存储层使用到，这个时候就能够使用存储引擎表里对应的索引列表筛选出正确的条件从而减少回表操作，而不是需要全部回表在service层中过滤。
比如WHERE name LIKE '张%' AND age = 20和
SELECT * FROM user WHERE zipcode = '431200' AND MONTH(birthdate) = 3;
**这里可能会有个疑惑**:为什么MONTH这个函数就可以使用索引下推但是如果我的第一个条件改为age+1=21就不能够使用数组下推了呢？因为Month这个函数是MySQL的内置函数，而age+1=21构成了存储引擎无法直接评估的算数表达式
