如果这是一道手写的题目，那么该怎么想呢？首先就会想到从后续遍历找最后一个元素，然后在中序遍历中找到这个节点，这个节点左边的所有元素都是左子树的节点，右边的节点是右子树的节点
如果写成算法的话，难点旧在于如何切割以及如何处理边界值
说实话，这一题与我写的[[654.最大二叉树]]有很大的相关性，我也是用到了切分两个集合的想法，而且那一题是我先写的。而且细细想的话，这个和分治思想很像有没有感觉。
```c++
class Solution {
public:
    TreeNode* buildTree(vector<int>& inorder, vector<int>& postorder) {
        if(inorder.size()==0||postorder.size()==0)
        return nullptr;
        return build(0,inorder.size(),inorder,postorder);
    }
    TreeNode* build(int left,int right,vector<int>&inorder,vector<int>&postorder)
    {
        if(postorder.empty())
        return nullptr;
        if(left>=right)
        return nullptr;
        int mid=postorder.back();
        postorder.pop_back();
        int index=left;
        for(index;index<right;++index)
        if(inorder[index]==mid)
        break;
        TreeNode* root=new TreeNode(mid);
        root->right=build(index+1,right,inorder,postorder);
        root->left=build(left,index,inorder,postorder);
        return root;
    }
};
```
这一手递归我觉得还是很灵性的，但是一开始忘记加上面的两个剪枝条件了，导致生成的树不对或者出现空集合pop_back的问题，不过我的执行用时只超过了60%
这个代码随想录的第一个答案耗时感觉挺长的，只超过了10%。。。但是说实话，我第一遍的时候竟然干瞪眼了，真是奇怪，明明[[654.最大二叉树]]的想法跟他差不多呀！
