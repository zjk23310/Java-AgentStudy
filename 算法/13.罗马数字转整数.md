#算法/哈希表 

# 题目

**13. 罗马数字转整数**

罗马数字包含以下七种字符：`I`，`V`，`X`，`L`，`C`，`D` 和 `M`。

| 字符 | 数值 |
|------|------|
| I | 1 |
| V | 5 |
| X | 10 |
| L | 50 |
| C | 100 |
| D | 500 |
| M | 1000 |

例如， 罗马数字 `2` 写做 `II`，即为两个并列的 1。`12` 写做 `XII`，即为 `X + II`。`27` 写做 `XXVII`，即为 `XX + V + II`。

通常情况下，罗马数字中小的数字在大的数字的右边。但也存在特例，例如 `4` 不写做 `IIII`，而是 `IV`。数字 `1` 在数字 `5` 的左边，所表示的数等于大数 `5` 减小数 `1` 得到的数值 `4`。同样地，数字 `9` 表示为 `IX`。这个规则只适用于以下六种情况：

- `I` 可以放在 `V`（5）和 `X`（10）的左边，表示 4 和 9
- `X` 可以放在 `L`（50）和 `C`（100）的左边，表示 40 和 90
- `C` 可以放在 `D`（500）和 `M`（1000）的左边，表示 400 和 900

给定一个罗马数字，将其转换成整数。

**示例 1：**
```
输入：s = "III"
输出：3
```

**示例 2：**
```
输入：s = "IV"
输出：4
```

**示例 3：**
```
输入：s = "MCMXCIV"
输出：1994
解释：M = 1000, CM = 900, XC = 90, IV = 4
```

**约束：**
- `1 <= s.length <= 15`
- `s` 仅包含字符 `I`、`V`、`X`、`L`、`C`、`D`、`M`
- 题目数据保证 `s` 是一个有效的罗马数字，且表示的整数范围在 `[1, 3999]` 之间

---

# 初见思路

核心规则就一句话：**小的在大的左边就减，否则就加**。

例如 `MCMXCIV` 手动拆解：

```
M  C  M  X  C  I  V
↓  ↓  ↓  ↓  ↓  ↓  ↓

1000, 后面C=100 < M   → 加 1000
 100, 后面M=1000 > C  → 减 100
1000, 后面X=10 < M    → 加 1000
  10, 后面C=100 > X   → 减 10
 100, 后面I=1 < C     → 加 100
   1, 后面V=5 > I     → 减 1
   5, 最后一个         → 加 5
```

结果：1000 - 100 + 1000 - 10 + 100 - 1 + 5 = **1994**

# 我的解法

用两个平行数组模拟映射关系，`find_inPlace` 线性查找字符下标：

```cpp
class Solution {
public:
    int romanToInt(string s) {
        char index[7] = {'I','V','X','L','C','D','M'};
        int num[7] = {1, 5, 10, 50, 100, 500, 1000};
        int size = s.size(), sum = 0;

        if (size == 0)       // 空串
            return 0;
        else if (size == 1)
            return num[find_inPlace(s[0], index)];
        else {
            for (int i = 1; i < size; ++i) {
                // 当前字符的下标 < 下一个字符的下标 → 小在大左 → 减
                if (find_inPlace(s[i-1], index) < find_inPlace(s[i], index))
                    sum -= num[find_inPlace(s[i-1], index)];
                else
                    sum += num[find_inPlace(s[i-1], index)];
            }
            sum += num[find_inPlace(s[size-1], index)];  // 最后一个直接加
        }
        return sum;
    }

    // 在 index 数组中查找字符 c 的下标
    int find_inPlace(char c, char* index) {
        int i;
        for (i = 0; index[i] != c; ++i);
        return i;
    }
};
```

**时间复杂度**：O(n)，每个字符调用一次 `find_inPlace`，数组只有 7 个元素可视为 O(1)

**空间复杂度**：O(1)

**思路解读**：

本质和官解完全一样——**比较相邻两个字符的大小**。用两个平行数组 `index[]`（字符）和 `num[]`（数值）模拟映射关系。`find_inPlace` 通过线性查找找到字符在 `index[]` 中的下标，下标就是数值的索引。

遍历时：
- `find_inPlace(s[i-1]) < find_inPlace(s[i])` → 当前值小于下一个值 → 减
- 否则 → 加
- 最后一个字符没有"下一个"，直接加

> [!tip] 为什么能用下标大小判断减法？
> 因为 `index[]` 按数值从小到大排列：`I(1) < V(5) < X(10) < L(50) < C(100) < D(500) < M(1000)`
> 所以下标大小 **等价于** 数值大小，`find_inPlace(s[i-1]) < find_inPlace(s[i])` 就是判断"当前值是否小于下一个值"。

# 官方解法

```cpp
class Solution {
private:
    unordered_map<char, int> symbolValues = {
        {'I', 1}, {'V', 5}, {'X', 10}, {'L', 50},
        {'C', 100}, {'D', 500}, {'M', 1000}
    };

public:
    int romanToInt(string s) {
        int ans = 0;
        int n = s.length();
        for (int i = 0; i < n; ++i) {
            int value = symbolValues[s[i]];
            // 当前值 < 下一个值 → 减；否则 → 加
            if (i < n - 1 && value < symbolValues[s[i + 1]]) {
                ans -= value;
            } else {
                ans += value;
            }
        }
        return ans;
    }
};
```

**时间复杂度**：O(n)

**空间复杂度**：O(1)（`unordered_map` 固定 7 个元素，可视为常数）

# 两种解法对比

| 对比项 | 我的解法（数组） | 官方解法（哈希表） |
|--------|-----------------|-------------------|
| 数据结构 | `char[]` + `int[]` 平行数组 | `unordered_map<char, int>` |
| 查找方式 | `find_inPlace` 线性遍历 | 哈希表直接索引 |
| 代码风格 | C 风格，手动实现 | C++ STL 风格 |
| 时间复杂度 | O(n) | O(n) |
| 空间复杂度 | O(1) | O(1) |
| 可读性 | 一般 | 更清晰直观 |
| 面试推荐 | ✅ 能用 | ✅✅ 更推荐 |

**本质上是同一个算法**，只是映射表的实现方式不同：

```
我的解法：字符 → find_inPlace 查下标 → num[下标] 取值
官  解：字符 → symbolValues[字符] 直接取值
```

官解的 `unordered_map` 省去了手动查找函数，代码更简洁。但从理解底层原理的角度，数组解法更能看出"本质就是一个查表"。

# 关键洞察

> [!tip] 罗马数字转整数的核心规则
> **只有 6 种特殊情况是"减法"**：IV(4)、IX(9)、XL(40)、XC(90)、CD(400)、CM(900)
>
> 它们的共同特征：**小值字符在大值字符左边**
>
> 所以只需要一条规则覆盖所有情况：
> - 当前值 **<** 下一个值 → **减**
> - 否则 → **加**
>
> 不需要单独写六个 if 去判断每种特殊情况。
